How to check
------------
Windows Command Prompt:
  certutil -hashfile skyrim-audit-share.zip SHA256

Windows PowerShell:
  Get-FileHash skyrim-audit-share.zip -Algorithm SHA256

macOS / Linux:
  shasum -a 256 skyrim-audit-share.zip

The printed hash must equal the SHA-256 above. certutil prints it lowercase,
and older Windows builds put spaces between byte pairs - ignore the spaces.
A match means the zip is the one built from the commit named above and was not
altered on the way to you.

If it does not match, download the zip again from the Releases page. If it still
does not match, do not run the exe.

What this proves, and what it does not
--------------------------------------
A matching hash proves the file is byte for byte the archive this repository's
workflow built from the commit above. It does not prove who built it: the exe is
unsigned, so Windows will still warn on first run. You can rebuild it yourself
with `go build -trimpath -ldflags "-s -w" -o skyrim-audit.exe .` on Windows.

Keeping this current
The workflow rebuilds the zip from source on every push to main and replaces the
release asset, so its hash changes when the source does. GitHub lists each
asset's current SHA-256 on the release page; if the release has been rebuilt
since this note was written, that value is the one to compare, and the "built
from" commit above names the build these numbers belong to.
