How to check
------------
Windows Command Prompt:
  certutil -hashfile skyrim-audit-share.zip SHA256

Windows PowerShell:
  Get-FileHash skyrim-audit-share.zip -Algorithm SHA256

macOS / Linux:
  shasum -a 256 skyrim-audit-share.zip

The printed hash must equal the SHA-256 above. certutil prints it lowercase,
and older Windows builds put spaces between byte pairs - ignore the spaces.
A match means the zip is the archive this repository's own workflow built from
the commit named above, not something repacked or replaced on the way to you.

If it does not match, download the zip again from the Releases page. If it still
does not match, do not run the exe.

What this proves, and what it does not
--------------------------------------
A matching hash proves the file is byte for byte the archive this repository's
workflow built from the commit above. It does not prove who built it: the exe is
unsigned, so Windows still warns on first run. You can build it yourself from
this repository with `go build -trimpath -ldflags "-s -w" -o skyrim-audit.exe .`
on Windows - the result may differ in bytes (the build stamps commit metadata)
but is the same program.

When this file is updated
The workflow builds and replaces the release zip when a release is published, or
when it is run by hand; a commit alone rebuilds nothing. So these numbers stay
correct until the next release: GitHub lists each asset's SHA-256 on the
release page, and if a new build has replaced the zip, that value is the one to
compare while this file still describes the previous build.
